How it's built

Two projects up close 🔍

The problem, how it works and the main decisions.

🗺️ Okeat

The problem

Information about kosher, vegan and gluten-free places is scattered and goes out of date.

How a claim becomes trusted

Claim added→Pending→3 confirmations→Verified

Main decisions

  • Rules live in the database: RLS and triggers protect the data even if someone calls the API without the site.
  • The map loads light points and clusters them, so 20,000 places stay fast.
  • Imported data stays labelled and never counts as community-verified.
📐 Architecture

🏨 DiviStay

The problem

In a group booking, one person usually pays for everyone and then has to collect from the others.

How a booking works

30-minute hold→Split the cost→Everyone pays→Confirmed

Main decisions

  • Room holds are atomic: a test races 32 threads for one room and exactly one wins.
  • Money is stored in whole agorot, so every split adds up exactly.
  • Payments are idempotent, so a double click can never charge twice.
📐 Architecture
